## 1. Qué es el sistema

Sistema real de producción para **programar y despachar concreto premezclado** en 7 planteles en 2 zonas de Honduras (Zona Norte y Zona Centro Sur). Reemplaza Excel + Google Sheets + AppSheet.

Regla central: **dos restricciones de flota independientes, una por zona** (Santa Marta → Zona Norte; Tegucigalpa → Zona Centro Sur). Nunca se consolidan.

## 2. Stack técnico

- **Next.js 16** (App Router, Turbopack) + **TypeScript** + **Tailwind 4**.
- **Prisma 7.8** con driver adapter `@prisma/adapter-pg`. Cliente en `app/generated/prisma/` (`@/app/generated/prisma/client`; singleton `lib/prisma.ts`).
- **PostgreSQL embebido** (`embedded-postgres`, PG 18, `:5433`, sin Docker). Ciclo de vida en `scripts/pg.ts`. Datos en `.pgdata/`. `DATABASE_URL` en `.env`; la url NO va en `schema.prisma` (vive en `prisma.config.ts`).
- **Auth.js v5** + `@auth/prisma-adapter` + `bcryptjs`. Sesión JWT. Credenciales + Google (env-gated).
- **Vitest** (BD `duracreto_test`).

### Comandos
`npm run dev` · `npm run db:seed` · `npm run db:reset` (bloqueado por guard de Prisma sin consentimiento) · `npm test` · `npx tsc --noEmit` · `npm run build`.

### Gotchas
- **Migración no-interactiva bloqueada**: usar `prisma migrate diff --from-config-datasource ./prisma.config.ts --to-schema ./prisma/schema.prisma --script` → escribir a mano `prisma/migrations/<ts>_<nombre>/migration.sql` → `prisma migrate deploy` → `prisma generate`.
- **Cliente Prisma stale**: tras cambiar esquema + generate, el `next dev` en ejecución usa el cliente viejo → hay que **matar el proceso, `rm -rf .next` y reiniciar** `npm run dev` (verificar puerto con `Get-NetTCPConnection -LocalPort 3000`).

## 5. Motor de asignación (`lib/motor/`)

- `planificador.ts` → **`planificarCombinacion(volumen, capacidades)`**: optimizador EXACTO de la mezcla de capacidades (min viajes → min ociosidad → menos grandes). 16→9+7, 18→9+9, 14→7+7, 25→9+9+7.
- `asignacion.ts` → **`recalcularCascadaPlanta`**: agenda + asigna mixers, consciente de horarios:
  - Reutilización de mixers por horario (un mixer hace varios viajes/día si sus ciclos no se traslapan).
  - Reparto de desgaste (elige el mixer más ocioso), propio antes que hub.
  - Tiempo de carga = `plantas.tiempo_alistamiento_min` + volumen/capacidad; tiempos de ruta desde `clientes.tiempo_*_referencia_min` (fallback 30/30 = `ruta_por_defecto`).
  - **`hora_solicitada` = LLEGADA al proyecto**: el inicio de carga se calcula hacia atrás. Solo el PRIMER viaje de la cola ancla el inicio de jornada (min llegada); el resto se encadena.
  - **`orden_dia`**: orden de atención por plantel+fecha; la cola se ordena por él; reordenable (`reordenarPedidoDia`, transacción + bitácora + recalcula todas las plantas).
  - **`hora_bloqueada`**: hora de llegada FIJA (piso duro), no se reprograma junto al resto.
  - **`frecuencia_entre_camiones_min`**: escalona los viajes del pedido.
  - `sugerirHoraDisponible` (autocompletar hora en el form). `confirmarRefuerzo`/`sugerirRefuerzo` (Paso 3). Despacho en vivo: `avanzarEstadoViaje`/`corregirHoraReal`/`editarVolumenViaje`/`cambiarOperadorViaje`/`reasignarMixer`.
- **Regla crítica**: el despacho sella `ts_*_real`; NUNCA toca los `hora_*` programados.

## 7. Modelo de datos (tablas principales)

`planteles` (hub_id), `plantas` (`tiempo_alistamiento_min`), `mixers` (identificador/placa opcionales, capacidad 7/9/11, plantel_base, operador), `bombas`, `operadores`, `asesores` (usuario_auth_id), `clientes` (**rutas fusionadas**: lat/long + `tiempo_*_referencia_min`, asesor_id, proyecto opcional), `disenos_mezcla`, `pedidos` (sacos_hielo, asesor_id, orden_dia, hora_bloqueada, frecuencia_entre_camiones_min, elemento, bomba_id, tipo_descarga), `viajes` (programación `hora_*` + ejecución `ts_*_real`), `solicitudes_anticipadas` (Programa Semana: plantel_id, sacos_hielo, elemento, frecuencia, estado, pedido_id), `metas_asesor` (asesor+año+mes+meta_m3), `bitacora_auditoria`, y Auth (`User`/`UserRole`/`Account`/`Session`/`VerificationToken`).

**Flota 100% dinámica** (agregar/quitar unidades o planteles es operación de datos, nunca código). Los números de flota NUNCA se hardcodean.
